## 妥当性の確認

- **LD + K は 27.220121m²（表示は 27.22m²）** で、図面画像に記載された **LDK 27.22m²** と表示桁で一致します。頂点座標からの面積は 27.528748m²（27.53m²）で図面より約 0.31m² 大きく、LD の 3 か所のドア（id33・34・38、幅の合計 2.4495m）の開口部の床を隣室へ移す補正で差を説明しています。奥行き 0.126m は、この差 0.3087m² をドア幅の合計で割って図面の値から逆算したもので、図面や JSON から読み取った寸法ではありません。壁の隙間 20cm − ドアの厚み 5cm ＝ 15cm という見立てでは 27.16m²（−0.22%）になります。詳細は [設計の補足](../design-notes.md) の「ドアの開口部による補正の試算」。
- **壁なし区間**が検出された箇所は、図面と照らし合わせるといずれも意図どおりです。
  - LD ⇄ K の境界（壁は一部だけで、残りはオープンキッチン）
  - 階段 ⇄ ホール（階段の上り口）、ホール ⇄ 玄関（上がり框）
- 全11部屋を既定条件で再計算し、JSON記載の面積・周長を同じ縮尺で換算した値と比較しました。頂点からの床面積の最大差は約3.11×10⁻¹⁵m²、周長の最大差は0mで、表示桁では全室一致します（比較対象は補正前の「頂点からの面積」）。これはJSON内部の整合性確認であり、図面記載の設計面積との一致を意味しません（既存のサンプル回帰テスト：`test/gpt-6/backend/analyzer/test_analyze.py::test_sample_file_results`）。

## 許容誤差 `tolerance_px` について

サンプルでは、実際に壁として採用された壁線と辺の 49 組で、壁の線分と部屋の輪郭のずれは中央値 0.82px、最大 7.16px でした（2026-09-20 に取り直し。以前は「最大でも 2〜3px」と書いていましたが誤りでした。壁の `lineWidth` は 5px です）。
既定値の 10px（約 14cm）は、このずれを十分に吸収しつつ、隣接する平行な壁（最短でも数十 px は離れています）を
誤って拾わない値として選んでいます。提出用の画面では、この値も固定しています。

- 部屋どうしの重なりは 9 か所、合計 0.18m²（床面積合計の約 0.4%）です。重複を除いた床面積（和集合）は 48.58m² です（2026-09-20 に `analyze_uncached` で確認。丸め前は 0.1773m² と 48.5760m²）。
