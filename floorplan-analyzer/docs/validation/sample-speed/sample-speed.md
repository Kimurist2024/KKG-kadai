# 同梱JSONでの速度確認（2026-09-18）

高速化の各段階は、部屋を複製して増やした入力や人工的な輪郭で倍率を報告しています。そこで、**課題で与えられた同梱の `sample/sample_mask.json` そのもの**で本当に速くなっているかを別に確かめました。

## 方法

- 比較対象: 変更前 ＝ `backend/benchmarks/baseline`（2026-09-14 時点、高速化を始める前の凍結コピー）、現行 ＝ `backend/app`
- 同じプロセスの中で変更前と現行を交互に 101 回ずつ実行し、中央値と p95（最近順位法）を取ります。計測の前に、既定条件と設定変更（天井高 3.1m・ドア高 2.2m）の両方で summary と rooms が変更前後で完全に一致することを確認します
- 測るのは `analyze` の呼び出しだけで、入力の検証・HTTP・JSON シリアライズは含みません
- 実行コマンド（アプリ直下）: `backend/.venv/bin/python scripts/measure_sample_speed.py 101 docs/validation/sample-speed/results.json`
- 生データ（各回のミリ秒）: [results.json](results.json)

## 結果（ミリ秒、中央値 / p95）

| 計測 | 変更前 | 現行 | 中央値の倍率 |
|---|---:|---:|---:|
| 初回解析（cold：幾何キャッシュを空にして既定条件で解析） | 3.019 / 3.607 | 3.875 / 4.668 | 0.78x |
| 設定変更後の再解析（warm：既定条件の直後に天井高・ドア高を変えて解析） | 2.981 / 3.689 | 0.906 / 1.146 | 3.29x |
| キャッシュ無効の直接計算（`analyze_uncached`） | 3.019 / 3.607 | 3.012 / 3.534 | 1.00x |

## 読み方

- 同梱JSONの**初回解析は速くなっていません**。むしろ約 0.9ms 遅くなっています。幾何計算そのもの（キャッシュ無効の直接計算）は変更前と同じ速さなので、差は解析結果をキャッシュに登録する処理（キーの計算と保存）の分だと考えています。3ms 規模の入力では、この固定費が相対的に大きく見えます
- 速くなるのは、同じ図面で設定（天井高・ドア高・縮尺）を変えて再解析するときです。キャッシュした幾何結果を再利用して約 3.3 倍になります
- 110 部屋・550 部屋の複製や 1,024 頂点の人工輪郭で報告した倍率は、同梱JSONには当てはまりません。それらは [性能測定](../algorithm-performance/report.md)、[計算結果を変えない高速化](../exact-speed/exact-speed.md)、[端点イベント走査の実測](../interval-sweep/interval-sweep.md) を参照してください
- 数値は 1 台のマシンでの 1 回の計測で、負荷によって変わります。上のコマンドで同じ条件の再計測ができます

## 改善後（同日中に対応）

上の結果を受けて、結果を一切変えずに初回解析を速くする変更を入れました。

変更点（`backend/app`）:

- cold 経路の dict 往復と再検証をやめ、型付きの応答を直接組み立てる（`analysis_cache._materialize_response`）。キャッシュには従来どおり `to_json` した bytes を保存し、warm 経路は従来のまま
- 総当たり経路（線分 64 本未満）に、STRtree 経路と同じ padding（許容距離＋EPS＋ulp）の外接矩形で候補を絞る事前判定を追加（`spatial.py`）。候補の入力順は維持
- 部屋どうしの重複判定で、外接矩形が重ならない組を Shapely 呼び出し前に除外し、`intersects` を一括呼び出し（`analyzer.py`）
- 区間・辺・頂点の結果を dict で組み立てて最後に一括検証、空／単一区間の短縮経路、辺長・検索枠の共有（`analyzer.py` / `geometry.py` / `topology.py`）
- 不採用: `model_construct` の全面適用（単体計測で通常のモデル生成より遅かったため）

結果（同じスクリプト、交互 101 回、ミリ秒、中央値 / p95。変更前の値は実行ごとに 2.9〜3.0ms の幅で揺れます）:

| 計測 | 変更前 | 改善後 | 中央値の倍率 |
|---|---:|---:|---:|
| 初回解析（cold） | 2.889 / 2.979 | 2.304 / 2.489 | **1.25x** |
| 設定変更後の再解析（warm） | 2.904 / 2.998 | 0.877 / 1.225 | 3.31x |
| キャッシュ無効の直接計算 | 2.889 / 2.979 | 1.999 / 2.086 | 1.44x |

複製入力（同梱図面を平行移動して複製した 110 部屋・550 部屋、初回解析の中央値、31 回）: 27.45ms / 165.50ms。直前の記録（[端点イベント走査の実測](../interval-sweep/interval-sweep.md) の 51.56ms / 318.88ms）より速く、悪化はありません。

確認方法:

- pytest 183 件 PASS。変更前の凍結実装との同等性テスト（3 入力 × 5 設定＋異常入力 7 種、浮動小数点の bit 差ゼロ）に加えて、全入力の cold / warm / uncached で各浮動小数点を bit 単位で比較するテスト（`test/gpt-6/backend/performance/test_cold_exact.py`）を追加しました
- [results.json](results.json) は改善後の計測で更新しています。改善前の値は上の表と git 履歴に残ります
