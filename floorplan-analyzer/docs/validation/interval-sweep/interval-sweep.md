# 端点イベントによる追加高速化（2026-09-17）

## 結論

直前の実装 `9f0e56b` と比較。**全入力で5倍という目標は未達**。
1,024頂点の人工輪郭では初回解析を7.91〜11.05倍に短縮したが、
同梱図面とその複製はほぼ同速。人工輪郭の倍率を実図面一般に適用してはいけない。

## 採用した方式

- 重複区間の交差: 開始・終了イベントをソートし、同時に存在する区間だけを比較する。
  [いもす法の原著者による解説](https://imoz.jp/algorithms/imos_method.html)
  （2012年、2026-09-17閲覧）の「出入り口だけを記録する」発想を利用した。
  ただし累積和で被覆数だけを得る通常のいもす法ではなく、元区間のIDを維持するイベント走査。
  座標は整数化・丸め・ラスタ化せず、元のmax/min、EPS判定、併合順を維持する。
  4,096組未満や特殊な区間は従来の全比較を使う。非重複区間の既存走査は変更しない。
- 自己交差判定: 64頂点以上では辺のx範囲の開始・終了を走査し、
  x/y境界箱が離れた辺を除外する。境界箱にはEPSと座標のULPに基づく余白を付ける。
  最終判定は元と同じ外積式・辺の順序。小規模や極端な座標では従来処理を残す。
- ビームサーチは不採用。今回の仕事は最適候補の探索ではなく全対象の計算であり、
  上位候補だけ残す近似は「以前の結果と変えない」という要件に適さない。

両方式とも候補が密集すると最悪ケースは二次時間のまま。
通常図面では壁区間が事前に併合されていて重複区間用経路の出番は少なく、
部屋の頂点数も小さいため今回の改善はほぼ効かない。

## 実測

同一Python環境・同一プロセス内。変更前後を交互の順序で9回計測した中央値。
初回は毎回キャッシュをクリアする。入力検証・HTTP・画面表示・レスポンスJSON化は含まない。
ウォームアップ各1回。GCは標準設定のまま。生データは [results.json](results.json)。

| 入力 | 初回: 変更前→後 ms | 倍率 | キャッシュ済み: 前→後 ms | キャッシュ無効: 前→後 ms |
|---|---:|---:|---:|---:|
| 同梱11部屋 | 3.690 → 3.748 | 0.984x | 0.853 → 0.865 | 2.925 → 2.941 |
| 穴・ドア・隙間デモ | 0.624 → 0.624 | 1.000x | 0.142 → 0.143 | 0.448 → 0.452 |
| 同梱図面の110部屋複製 | 51.384 → 51.561 | 0.997x | 9.723 → 9.697 | 34.085 → 32.223 |
| 同梱図面の550部屋複製 | 321.427 → 318.884 | 1.008x | 113.064 → 114.824 | 193.166 → 198.797 |
| 人工円・1024頂点・壁なし | 398.356 → 36.046 | 11.051x | 11.394 → 18.679 | 385.879 → 17.528 |
| 人工正方形・1024頂点・4壁 | 405.620 → 51.299 | 7.907x | 16.203 → 10.100 | 399.242 → 33.382 |

重複区間各1,000本の関数単体: 192.129 → 4.138 ms（46.43倍）。
これは解析全体の倍率ではない。キャッシュヒット時は今回の幾何処理を通らないため、
その速度改善は主張しない。特に人工円のキャッシュ済み計測は遅くなっており、
この計測からキャッシュ経路の高速化や無退行を保証することはできない。

## 一致確認

- 上記6入力 × 5設定（標準・高さ・縮尺・許容幅0・許容幅2.5）× cold/warm。
- 同梱図面は幾何補正モードも確認。
- 同梱図面を微小ランダム変形した30入力 × cold/warm。
- 全レスポンスの型・配列順・ID・警告・値を比較。
  浮動小数点は許容誤差なしの `float.hex()` 比較で **1,574,736個一致**。
- 回帰テスト41件追加: 重複/EPS付近/符号付きゼロを含む区間、
  63/64/65/128/256頂点、逆順・交差・重複頂点・ほぼ直線・大きな座標、候補削減。

検証した入力での完全一致であり、すべての未検証入力に対する数学的証明ではない。
壁面積や床面積の公式、縮尺、合算順序、API・UIは変更していない。
