# 開発サーバーの起動時間

## 計測条件

- 計測日: 2026-09-17
- 依存関係をインストール済みのローカル開発環境
- ブラウザ UI は操作せず、CLI から HTTP で計測
- フロントエンドは Next.js 16.3.5 (Turbopack)
- 「Web が開く」はトップページの HTTP 200 応答までと定義

## 変更前

ルートの `scripts/start.sh` 実行後、最初のトップページ応答までは 1.38〜1.53 秒でした。
内訳を単独で測ると、Next.js 自体の Ready は約 0.22 秒ですが、最初の `GET /` に
オンデマンドコンパイルが走るため 0.57〜0.80 秒かかります。2 回目以降の `GET /` は
0.011〜0.015 秒でした。バックエンドの health 応答までは 0.59〜0.80 秒でした。

## 改善内容

- 初回の Python 依存セットアップと npm セットアップを並列化
- 8000/5173 番ポートの解放待ちを並列化
- FastAPI と Next.js のプロセスを並列起動
- API health 確認とトップページの初回コンパイルを並列化
- 両方が HTTP 応答できてから `== 起動完了` を表示
- `npx` の探索を介さず、インストール済みの Next.js 実行ファイルを直接起動
- `BACK_RELOAD=0` でバックエンドの reload 監視を省略可能

## 変更後

通常設定（バックエンドの自動リロード有効）では、コマンド開始から `== 起動完了` まで
1.103 秒でした。Next.js Ready は 0.260 秒、トップページの先行コンパイルは 0.227 秒、
`== 起動完了` 表示直後の実アクセスは 0.0170 秒で HTTP 200 を返しました。

自動リロードを無効にした確認でも、起動完了後のトップページは 0.0188 秒、API health は
0.0016 秒で、ともに HTTP 200 を返しました。

初回セットアップの並列化は、既存の依存ディレクトリを破壊せずに実装確認したため、
クリーン環境での所要時間は未計測です。直列時の合計時間ではなく、Python と npm の
うち遅い方に概ね収束する構成です。
