### 1. スマホで主要な結果を画面内に収める  [影響: 高]  [実装コスト: 中]
- **現状の問題**：画像3では右端の壁面積・集計カード・操作ボタンが切れています。`styles.css` は段組み変更のみで、カードの `min-width:120px` やグリッド子要素の最小幅への対処が不足しています。

### 2. 部屋を選んだ直後に算出根拠へ進める  [影響: 高]  [実装コスト: 中]

- **提案**：PC は左に図面、右に「部屋一覧／選択部屋の詳細」の切替を配置。選択時に「ホール｜壁面積 13.45 m²｜算出根拠を見る」を表示します。スマホはこの選択バーから詳細へ移動し、「図面で確認」で同じ部屋・辺の表示に戻れるようにします。

### 3. 壁面積の意味と控除範囲を明確にする  [影響: 高]  [実装コスト: 小]
- **現状の問題**：画像2の「開口」と「ドア」は区別が分かりにくく、共有壁の両面計上は表下の小さな注記のみ。`RoomTable.tsx` は正常な壁なし区間にも警告色を使っています。
- **提案**：「壁面積」を「壁面積（ドア控除後）」、「開口」を「壁なし長」、「ドア」を「控除対象ドア幅」に変更。合計付近に「各室の内壁面積の合計・共有壁は両面計上・窓は控除対象外」を表示します。壁なし長は通常の数値色とし、図面との対応マーカーだけ橙色に。定義はタップ可能な説明ボタンで確認できるようにします。

### 4. 計算条件の確認と未反映状態を分かりやすくする  [影響: 高]  [実装コスト: 中]

- **提案**：「適用中の計算条件」として天井高・ドア高・スケールを項目別に表示。入力では「画像上［96.7］px ＝ 実寸［1.365］m」を一組にし、許容誤差は「詳細設定」へ。編集中は「変更は未反映です」、再計算中は「前回の結果を表示中」、完了時は「結果を更新しました」と表示します。

### 5. 図面の拡大と辺の選択をタップでも完結させる  [影響: 高]  [実装コスト: 中]
- **現状の問題**：`FloorPlanView.tsx` の拡大操作はスライダーのみ。`RoomDetail.tsx` の辺の行はホバーで強調されるため、スマホでは同じ確認操作ができません。

### 6. 算出根拠を実務の読み順に整理する  [影響: 中]  [実装コスト: 小]
- **現状の問題**：画像2と `RoomDetail.tsx` では、結果・px 座標・輪郭 ID・計算式が同時に並び、壁面積を確認するための情報が埋もれています。
- **提案**：詳細先頭を「壁面積 13.45 m²」にし、直下に「壁部分 18.27 − ドア控除 4.82 ＝ 13.45 m²」を表示。その下に代入式と辺別内訳を置きます。座標・線分 ID・JSON 記載値との差は「元データとの照合」に折り畳み、必要時に確認できるようにします。

### 7. 注意事項から対象の部屋へ移動できるようにする  [影響: 中]  [実装コスト: 中]
- **現状の問題**：画像2は「注意（2件）」だけでは内容が分かりません。`App.tsx` は警告文字列の一覧で、図面・表への導線がありません。
- **提案**：サンプルでは「部屋名未設定：2室」と要約し、該当行にもラベルを表示。「対象を確認」で部屋を選択します。名称不足と計算値に関わる注意を分け、後者を優先表示。安定した連携には警告の種類・部屋 ID を持つ構造化データが望まれます。

### 8. 初期画面の主操作をファイル選択にする  [影響: 中]  [実装コスト: 小]
- **現状の問題**：画像1と `UploadPanel.tsx` では唯一の青いボタンがサンプル用で、自分のデータを読み込む操作が説明文に埋もれています。
- **提案**：主ボタンを「JSON ファイルを選択」、副ボタンを「サンプルで試す」に変更。「図面の解析済み JSON から、部屋別の床面積・壁面積を確認できます」と説明し、入力形式の詳細は折り畳みます。ドロップ領域は通常のコンテナとし、ファイル選択は独立したボタンで操作できる構造にします。

## Round 3 — Claude の回答

- A1 (スマホの横はみ出し) は **撮影方法の問題** だった。ヘッドレス Chrome はウィンドウ幅の最小値が 500 px のため、375/420 px 指定でもビューポートは 500 px で描画され、画像だけが切り取られていた。実測 (`document.documentElement.scrollWidth` と各要素の `getBoundingClientRect`) では、横スクロール枠内の内訳表以外にはみ出す要素はない。幅 375 px の iframe に埋め込んで再撮影し、確認した。
- A2/B3 (Enter/Space の伝播): 行の `onKeyDown` は `e.target === e.currentTarget` のときだけ処理するよう修正。
- A5: 粗いポインタ環境では `btn-sm` も最小高 40 px に統一。
- A7: 表示名の比較対象を JSON の元の `room_name` にし、再編集で変更なしでも上書きが消えないようにした。「表示名を上書き中」タグを追加。
