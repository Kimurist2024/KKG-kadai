# 部屋選択時の表示処理の改善

2026-09-14。対象は解析済み図面の部屋クリック。API通信や幾何計算は発生せず、既に取得した結果をReactで表示する操作。

## 変更

- `format.ts`: 桁数ごとに `Intl.NumberFormat` を再利用。数値自体はキャッシュせず、図面や縮尺変更時も最新値を整形する。
- `RoomTable.tsx`: 行をmemo化し、選択・ホバー・内容が変わった行だけ更新。
- `RoomDetail.tsx`: memo化し、閉じている「元データとの照合」の本文を生成しない。開くと表示、部屋切替で閉じる。
- `App.tsx`: 空の表示名マップと詳細欄のコールバック参照を安定させる。

LLMのKVキャッシュやサーバー側のKVストアを追加しても、この操作には効かない。今回再利用するのは端末内の表示処理で、外部サービスや追加費用はない。

## 計測と検証

Node.js / Vitest 3.2.7 / jsdom、同梱サンプルの実際のAPI結果（11部屋）をfixture化。実APIと画像AIはモックし、33回順番に部屋を選択。最初の11回を除いた22回で `fireEvent.click` の同期更新完了までを測定。

| 指標 | 修正前の記録 | 修正後の記録 |
|---|---:|---:|
| 部屋選択 中央値 | 8.896 ms | 3.581 ms |
| 部屋選択 p95 | 12.194 ms | 6.600 ms |

実行負荷で変動するため速度の閾値はテストに固定しない。ブラウザのレイアウト・描画時間、端末差、実ユーザーのINPは含まない。computer use禁止のためブラウザ操作・目視検証は未実施。

数値整形のみの予備計測（10,000値、4回）は従来109.6〜113.6 ms、整形器再利用2.0〜2.3 ms。この約50倍という差は数値整形だけであり、画面全体の改善率ではない。
